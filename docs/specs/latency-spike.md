# Spec: Milestone 1 latency spike (Android first)

Status: implemented on Android (Milestone 1). Open: the 50 ms gate on a real phone with the probe, and the H700 half.

## Purpose

Prove on Android that a libretro core (mGBA) can run inside the Flutter app with
input-to-photon latency under 50 ms, a stable 60 fps and no audio crackle, and pick
the composition path for the rest of the project: Flutter `Texture` versus a
`SurfaceView` platform view. The H700 handheld half of the spike waits until that
hardware is on the rig (CLAUDE.md §6).

## Scope

In: mGBA libretro core built for Android, a native emulator thread, audio through
Oboe, gamepad/keyboard input read in the Activity before Flutter, both composition
paths behind a switch, in-app software latency and pacing metrics, our own latency
test ROM.

Out: library UI, skins, save-state UI, shaders, GLES/Vulkan renderer (spike blits on
the CPU; the GPU path comes with shaders), Swappy (needs the GPU path), handhelds.

| Latency test ROM | `host/tests/roms/latency/` | Our own GBA ROM generated by a Python script (no toolchain, no Nintendo logo): mode 3, screen black, white while A is held, plus a tone while A is held. GPL-3.0. |

## Composition paths

Both feed the same native blitter, which writes RGB565 or RGBX8888 into an
`ANativeWindow` (`ANativeWindow_lock` / `unlockAndPost`):

- **SurfaceView**: a platform view hosting a `SurfaceView`; its `Surface` goes to native.
- **Texture**: `TextureRegistry.SurfaceProducer`; its `Surface` goes to native, and Flutter
  composites the texture.

Switching paths restarts the surface, not the core.

## Timing

- The emulator thread runs one core frame per display vsync on 60 Hz panels, using
  `AChoreographer` callbacks. On 90/120 Hz panels it runs a frame when the 59.73 Hz
  (GBA) or 60 Hz frame deadline has passed, so speed stays correct.
- Audio: Oboe, `PerformanceMode::LowLatency`, `SharingMode::Exclusive` when available,
  float or int16 stereo at the device's native rate. The core's audio is resampled
  (linear is fine for the spike) and written to a lock-free ring buffer. The resampling
  ratio is nudged by ±0.5 % to keep the ring buffer near its target fill (dynamic rate
  control), so video drives timing and audio never starves.
- Input: `Activity.dispatchKeyEvent` / `dispatchGenericMotionEvent` map gamepad and
  keyboard events to a RetroPad mask and pass them to native through JNI before Flutter
  sees them. Every change carries its `eventTime` in nanoseconds (uptime).

## Software metrics (until the photodiode probe exists)

Shown in the overlay and logged as one JSON line per second under the tag `Dena`:

- `input_to_post_ms`: from an input event's `eventTime` to `unlockAndPost` of the first
  frame the core produced after polling that input. p50 / p95 / max.
- `present_ms` (SurfaceView path only, API 29+): extra time from post to the display's
  present time, read from frame timestamps where the platform provides them. Otherwise
  `null`.
- `frame_interval_ms`: p50 / p99 and missed-frame count (an interval over 1.5× the target).
- `audio_xruns`: Oboe underruns since start; `audio_buffer_ms`: current ring buffer fill.

These numbers are a lower bound on input-to-photon latency (they leave out panel
scan-out and touch/USB/Bluetooth input lag). The Milestone 1 gate is confirmed with the
probe (docs/specs/rig.md) once the user adds it.

## Edge cases

- Surface destroyed (app backgrounded, rotation): the emulator thread pauses, audio
  pauses, state stays in memory; it resumes on the new surface.
- Gamepad disconnected: the core stays paused until input resumes (full pause-menu
  behaviour is Milestone 2).
- ROM with the wrong extension or a core load failure: an error snackbar; nothing crashes.
- 90/120 Hz panels: speed must stay within 0.5 % of native (checked in tests by counting
  core frames per wall-clock second).

## Acceptance tests

- Host (CI, desktop): the mGBA core runs the latency test ROM through `dena-harness`.
  Goldens: screen black with no input, white after a replay presses A, black again
  after release; the audio hash changes while A is held; save-state round trip passes.
- Kotlin unit tests: key/motion event → RetroPad mask mapping for Xbox, DualSense and
  generic HID layouts and for the keyboard.
- Native unit tests (host-side build of the ring buffer and resampler): no underrun at a
  steady state; ratio adjustment converges to the target fill.
- On-device integration test (`app/integration_test/spike_test.dart`), run on an Android
  emulator in CI: for each path, start the test ROM, send keys through the Activity's
  `dispatchKeyEvent` (the same path a gamepad takes in the app), and assert by pixel
  readback that the frame is black, white while RetroPad A is held, black after release,
  and unaffected by RetroPad B. The metrics are printed to the job summary. Frame pacing
  is not asserted on the emulator (software GPU); the gate is measured on a real device.
- Decision record: `docs/decisions/0001-composition-path.md` compares both paths on the
  metrics above and picks one.
